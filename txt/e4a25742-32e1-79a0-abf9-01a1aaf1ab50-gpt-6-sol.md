**Wozu kann ich `git` nutzen, wenn ich nicht programmiere?** Immer dann, wenn Dokumente über längere Zeit entstehen und man Änderungen nachvollziehen möchte. Das können beispielsweise die Texte einer Website, eine Dokumentation, Verträge in einem Textformat, Unterrichtsmaterialien, Übersetzungen oder die Unterlagen für ein Buch sein. Statt Dateien mit Namen wie `Konzept_final_neu_2` anzulegen, hält man die Arbeitsschritte als Commits fest: «Einleitung überarbeitet», «Rückmeldungen eingearbeitet» oder «Fassung für die Veröffentlichung erstellt». Später lässt sich nachsehen, wann eine Formulierung geändert wurde und wie sie vorher lautete.

Auch bei der Zusammenarbeit hilft das. Mehrere Personen können an denselben Unterlagen arbeiten, ihre Änderungen zusammenführen und besprechen, bevor sie übernommen werden. Am besten funktioniert das mit Textdateien. Wer hauptsächlich mit Word- oder Excel-Dateien arbeitet, kann `git` ebenfalls nutzen, profitiert aber weniger von der detaillierten Anzeige einzelner Änderungen.

**Brauche ich dafür einen Server oder GitHub?** Nein. `git` arbeitet auf dem eigenen Computer. Man kann ein Repository anlegen, Commits erstellen und frühere Versionen wiederherstellen, ohne eine Internetverbindung oder ein GitHub-Konto zu haben. Ein Dienst wie GitHub wird interessant, wenn man das Repository mit anderen teilen oder von mehreren Geräten aus darauf zugreifen möchte. Dann sollte man allerdings bewusst entscheiden, wer Zugriff auf die Dateien erhält. Ein privates Repository ist nicht öffentlich, liegt aber trotzdem bei einem externen Anbieter.

**Und brauche ich Linux?** Ebenfalls nein. `git` läuft unter Linux, Windows und macOS. Man muss dafür nicht einmal dauerhaft mit Befehlen im Terminal arbeiten: Programme mit grafischer Oberfläche machen viele der üblichen Schritte per Mausklick zugänglich. GitHub Desktop ist beispielsweise für Windows und macOS erhältlich und lässt sich auch für lokale Repositories verwenden.

Eine Gewohnheit muss man sich trotzdem aneignen: `git` speichert nicht nach jeder Bearbeitung automatisch eine neue Version. Man entscheidet selbst, wann ein Arbeitsschritt abgeschlossen ist, und erstellt dann einen Commit. Dafür erhält man eine Versionsgeschichte, die mehr aussagt als eine Sammlung von Dateien mit immer längeren Namen.
