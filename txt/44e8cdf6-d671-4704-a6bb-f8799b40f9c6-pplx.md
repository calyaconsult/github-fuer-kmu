# Ich bin ein Ein-Mann-Unternehmen. Wozu kann ich, abgesehen von Programmier-Projekten, GitHub brauchen?

Ja — GitHub kann für dich als Ein-Mann-Unternehmen vor allem als **versionsichertes Arbeits- und Wissenssystem** dienen, nicht nur als Code-Ablage. Besonders sinnvoll ist es, wenn du Dokumente, Workflows, Recherchen und wiederkehrende Prozesse nachvollziehbar versionieren willst.[^1_1][^1_2]

## Praktische Einsatzfelder

| Einsatz | Was du dort ablegst | Warum es sich lohnt |
| :-- | :-- | :-- |
| **Kunden- und Projektarchive** | Briefings, Angebote, Konzepte, Meeting-Notizen, Checklisten, Abschlussberichte | Jede Änderung bleibt datierbar; du kannst später exakt nachvollziehen, welche Fassung wann galt. [^1_2] |
| **Beratungs-Playbooks** | Standardvorgehen für SEO-Audits, KI-Readiness-Checks, Website-Relaunches, Content-Strategien | Du entwickelst deine Methodik iterativ weiter, statt sie in verstreuten Word-Dateien zu verlieren. |
| **Vorlagen-Bibliothek** | Angebotsvorlagen, Onboarding-Formulare, Prompt-Bibliotheken, Workshop-Abläufe, E-Mail-Bausteine | Zentrale Quelle; Änderungen lassen sich gezielt testen und bei Bedarf zurückrollen. |
| **Redaktionelle Projekte** | Buchmanuskripte, Artikel, Glossare, Recherchenotizen, Übersetzungen, Lektoratsversionen | Markdown eignet sich gut für Textarbeit; Git zeigt Änderungen zwischen Entwurf, Lektorat und Finalfassung. |
| **Wissensdatenbank** | Tools, Anbieter, Preismodelle, Gesetzes-/Compliance-Hinweise, Recherchequellen, Entscheidungslogbücher | GitHub Repositories können Dokumentation, Diskussionen und Aufgaben zusammenführen. [^1_1][^1_2] |
| **Leichte Projektsteuerung** | Issues für To-dos, Ideen, Kundenanfragen, Verbesserungen; Projects als Board oder Tabelle | Du kannst Aufgaben, Meilensteine und Prioritäten verwalten, ohne eine separate PM-App zu benötigen. [^1_1][^1_3] |
| **Öffentliches Portfolio** | Ausgewählte Methoden, Fallstudien, Whitepaper, Open-Source-Vorlagen, Beispiel-Workflows | GitHub eignet sich auch, um Arbeit sichtbar zu machen und Fachkompetenz zu demonstrieren. [^1_1][^1_4] |
| **Website und Dokumentation** | Blog, Helpcenter, Handbücher, FAQ, Produktseiten über GitHub Pages | GitHub unterstützt ausdrücklich das Hosting von Dokumentation und Websites. [^1_1] |
| **Automatisierung** | Geplante Skripte für Monitoring, Berichte, Datenabgleiche oder Content-Workflows via GitHub Actions | GitHub Actions kann Workflows automatisieren; das ist auch ohne klassisches Softwareprojekt nützlich. [^1_5][^1_6] |

## Besonders passende Setup-Ideen

### 1. „Consulting OS“

Ein privates Repository mit:

- `clients/` — je Kunde ein Ordner mit Briefing, Angebot, Projektstatus
- `templates/` — Angebote, Audits, Workshop-Pläne
- `methods/` — deine wiederkehrenden Beratungsansätze
- `prompts/` — geprüfte KI-Prompts und Automatisierungsrezepte
- `decisions/` — warum du ein Tool, eine Methode oder eine Preislogik gewählt hast

Das ersetzt keinen DSGVO-konformen Kundenspeicher für sensible Originalunterlagen, ist aber stark für deine **eigene Arbeitsmethodik und das Projektgedächtnis**.

### 2. Redaktions-Repository

Für Buch-, Newsletter- oder Website-Projekte:

- `manuscript/` — Kapitel als Markdown
- `research/` — Quellen, Zitate, Notizen
- `editorial/` — Lektorats- und Produktionschecklisten
- `issues/` — offene Fragen, Recherche-Lücken, Korrekturaufgaben

Der Vorteil: Du kannst textliche Änderungen zeilenweise nachvollziehen und alte Fassungen jederzeit wiederherstellen. Ein Repository enthält Dateien **und deren gesamte Revisionshistorie**.[^1_2]

### 3. Öffentliche Vertrauens-Basis

Ein öffentliches Repo könnte etwa enthalten:

- Eine kurze Methodenbeschreibung deines KI-Adoptions-Checks
- Eine Checkliste für SME-Website-Audits
- Vorlagen für KI-Richtlinien oder Prompt-Standards
- Ausgewählte, anonymisierte Fallbeispiele

Das ist weniger ein Sales-Kanal als ein **glaubwürdiger Kompetenznachweis** — ähnlich einem öffentlichen Arbeitsbuch.

## Wann GitHub nicht die beste Wahl ist

- Für vertrauliche Kundendaten, Verträge oder personenbezogene Daten solltest du primär einen geeigneten Schweizer/EU-Cloud- oder lokalen Speicher nutzen; GitHub kann allenfalls stark anonymisierte Arbeitsvorlagen enthalten.
- Wenn du vor allem visuell arbeitest, sind Notion, Obsidian oder Google Workspace oft angenehmer.
- Wenn Kund:innen aktiv mitarbeiten sollen, braucht GitHub etwas Einarbeitung; für einfache Freigaben ist es manchmal zu technisch.


## Mein pragmatischer Start

Beginne mit **einem privaten Repository namens `consulting-os`** und lege dort nur drei Dinge ab:

1. Deine wichtigsten Beratungs-Checklisten
2. Deine Angebots- und Onboarding-Vorlagen
3. Ein Issues-Board mit „Ideen“, „Kundenprojekte“ und „Verbesserungen“

Nach ein paar Wochen siehst du, ob dir die Versionshistorie und die Verknüpfung von Dokument, Aufgabe und Entscheidung wirklich nutzen. GitHub ist dafür grundsätzlich geeignet: Es vereint Ablage, Versionshistorie, Aufgaben, Diskussionen, Dokumentation und Automatisierung an einem Ort.[^1_1][^1_2]

# Was kostet GitHub?

Für dich als Ein-Mann-Unternehmen ist GitHub praktisch kostenlos: Der **Free-Plan** kostet **0 USD pro Monat** und umfasst unbegrenzt öffentliche und private Repositories.[^2_1][^2_2]

## Aktuelle Pläne

| Plan | Preis | Für dich relevant? |
| :-- | --: | :-- |
| **Free** | 0 USD/Monat | Ja — private Repositories, Issues, Projects, 2.000 Actions-Minuten/Monat, 500 MB Packages-Speicher. [^2_1][^2_2] |
| **Team** | 4 USD pro Nutzer/Monat; für die ersten 12 Monate laut Preisseite 4 USD, mit Jahresvorauszahlung teils 3,67 USD | Eher nicht nötig, solange du allein arbeitest; bringt u. a. geschützte Branches, Codespaces und 3.000 Actions-Minuten. [^2_1][^2_2][^2_3] |
| **Enterprise Cloud** | ab 21 USD pro Nutzer/Monat | Nicht relevant für ein Solo-Unternehmen; richtet sich an Organisationen mit SSO, Compliance- und Sicherheitsanforderungen. [^2_1][^2_4] |

## Was das für dich bedeutet

- **0 USD** reicht für dein „Consulting OS“, Textprojekte, Vorlagen, Recherche-Archive, Issues und einfache Automatisierungen völlig aus.[^2_2][^2_1]
- **GitHub Actions** sind im Free-Plan mit 2.000 Minuten pro Monat enthalten; für öffentliche Repositories sind Standard-Runner grundsätzlich gratis.[^2_5][^2_1]
- Kosten können erst durch hohe Nutzung entstehen, etwa viele Actions-Minuten, zusätzliche Speicher-/Bandbreite oder Premium-Add-ons wie Copilot bzw. Advanced Security.[^2_6][^2_1]
- Die Preise sind in USD ausgewiesen; in der Schweiz kommt je nach Zahlungsart und Kreditkartenanbieter noch ein Umrechnungs- bzw. Fremdwährungszuschlag hinzu.

**Praktische Empfehlung:** Starte mit **GitHub Free**. Ein Upgrade auf Team lohnt sich erst, wenn du gezielt geschützte Branches, mehr Actions-Minuten, Codespaces oder erweiterte Kollaborationsfunktionen brauchst.[^2_1][^2_2]

# Was kostet GitHub Copilot zusätzlich

Als Ein-Mann-Unternehmen zahlst du für GitHub Copilot zusätzlich **ab 0 USD** — es gibt einen begrenzten Gratis-Plan. Für regelmässige Nutzung ist **Copilot Pro mit 10 USD pro Monat** die passende Einzelplatz-Stufe.[^3_1][^3_2]

## Copilot-Preise

| Plan | Preis | Enthaltene AI-Credits/Monat | Sinnvoll für dich? |
| :-- | --: | --: | :-- |
| **Copilot Free** | 0 USD | begrenzte Zuteilung | Zum Ausprobieren; nur eingeschränkte Funktionen und Modellwahl. [^3_1][^3_2] |
| **Copilot Pro** | 10 USD/Monat | 1.500 Credits | Wahrscheinlich die richtige Wahl für Solo-Nutzung. [^3_1][^3_3] |
| **Copilot Pro+** | 39 USD/Monat | 7.000 Credits | Nur wenn du intensiv Premium-Modelle und Agenten nutzt. [^3_1][^3_3] |
| **Copilot Max** | 100 USD/Monat | 20.000 Credits | Für sehr hohe, agentenlastige Nutzung; für dich meist überdimensioniert. [^3_1][^3_3] |
| **Copilot Business** | 19 USD pro Sitz/Monat | 1.900 Credits pro Nutzer | Eher für Organisationen: zentrale Verwaltung, Richtlinien und Cloud-Agenten. [^3_1][^3_2] |
| **Copilot Enterprise** | 39 USD pro Sitz/Monat | 3.900 Credits pro Nutzer | Benötigt GitHub Enterprise Cloud; für ein Solo-Unternehmen nicht relevant. [^3_1][^3_4] |

## Zusatzkosten verstehen

Seit dem 1. Juni 2026 rechnet GitHub Copilot die Nutzung über **GitHub AI Credits** ab: 1 Credit entspricht 0,01 USD. Die Credits decken vor allem Chat, Agenten, Code-Review und die Nutzung bestimmter Modelle; normale Code-Vervollständigungen und „Next Edit“-Vorschläge bleiben in bezahlten Plänen unbegrenzt und werden nicht extra über Credits abgerechnet.[^3_5][^3_6][^3_1]

Überschreitest du dein monatliches Kontingent, fallen zusätzliche Credits zu 0,01 USD je Credit an. Bei **Copilot Pro** entspricht dein Kontingent von 1.500 Credits somit einem Nutzungswert von 15 USD; die Grundgebühr bleibt dennoch bei 10 USD monatlich.[^3_6][^3_1]

## Empfehlung für dich

- **Kostenlos starten:** Copilot Free, um Editor-Integration, Chat und grundlegende Automatisierung zu testen.[^3_2]
- **Wenn du es regelmässig nutzt:** Copilot Pro für 10 USD/Monat — als Einzelperson einfacher und günstiger als Business.[^3_7][^3_1]
- **Business nur bei Bedarf:** 19 USD/Monat lohnen sich vor allem, wenn du zentrale Lizenzverwaltung, Richtlinien, IP-Indemnity oder organisationsweite Steuerung brauchst; das ist bei einem Ein-Mann-Betrieb meist nicht der Fall.[^3_2][^3_7]

In der Schweiz kommen zur USD-Grundgebühr je nach Zahlungsweg noch Währungsumrechnung und mögliche Kartengebühren hinzu.

# Welche meiner Kunden könnten von GitHub ebenfalls profitieren? Es handelt sich um kleinere Reisebüros, Berater (Ernährung, Fitness, Persönlichkeitsentwicklung), Buchautoren und Handwerker.

Von deinen genannten Kundengruppen profitieren **Buchautoren am deutlichsten**, gefolgt von Beratenden. Reisebüros und Handwerker können GitHub nutzen, aber meist eher als **dein internes Projekt- und Automatisierungswerkzeug** als als Tool, das du ihnen direkt aufdrückst. Deine Kundschaft arbeitet häufig stark in Excel und ohne daten- oder technikaffine interne Rollen — das spricht für einfache, von dir betreute Lösungen statt einer GitHub-Einführung beim Kunden.

## Passung nach Kundentyp

| Kundentyp | GitHub-Potenzial | Sinnvolle Anwendung | Realistischer Einstieg |
| :-- | :-- | :-- | :-- |
| **Buchautoren** | Sehr hoch | Manuskriptversionen, Recherche, Lektorats-Feedback, Glossar, Veröffentlichungs-Checklisten | Ein Repository pro Buch; Kapitel als Markdown, Issues für offene Recherche- und Korrekturpunkte |
| **Berater:innen** | Hoch | Methoden, Workshop-Unterlagen, KI-Prompt-Bibliothek, Kundenvorlagen, Wissensdatenbank | Ein privates „Practice OS“ mit Vorlagen und Projektdokumentation |
| **Reisebüros** | Mittel | Website-/SEO-Inhalte, Reiserouten-Vorlagen, Angebotsbausteine, FAQ, Content-Kalender | Vor allem von dir verwaltetes Repo für Website, Inhalte und wiederkehrende Angebote |
| **Handwerker** | Mittel bis niedrig | Website, Offerten- und Angebotsvorlagen, Checklisten, Dokumentation, einfache Automatisierungen | Du betreibst das Repo; der Handwerker sieht nur Ergebnisse in vertrauten Tools |

## Buchautoren: klarster Fall

Für Autor:innen ist GitHub fast ein ideales Redaktionssystem: Texte lassen sich kapitelweise als Markdown ablegen, jede Überarbeitung bleibt nachvollziehbar, und alte Fassungen sind wiederherstellbar. Issues eignen sich für Recherchefragen, Plotlücken, Rechtschreibkorrekturen oder Verlagsaufgaben; ein Repository bündelt Dateien und deren Revisionshistorie.[^4_1]

Ein möglicher Aufbau:

- `manuskript/` — Kapitel und Anhang
- `recherche/` — Quellen, Interviewnotizen, Zitatprüfungen
- `produktion/` — Lektorats- und Druckchecklisten
- `issues/` — „Kapitel 4: Quelle prüfen“, „Titelvarianten bewerten“

Der Vorteil gegenüber Word: keine Dateinamen wie `Manuskript_final_v7_NEU_korrigiert.docx`, sondern ein sauberer Änderungsverlauf.

## Berater:innen: stark bei Wissensarbeit

Ernährungs-, Fitness- und Persönlichkeitsberater:innen haben oft wiederkehrende Inhalte: Erstgespräche, Anamnese, Übungspläne, Ernährungsvorlagen, Workshop-Unterlagen, Social-Media-Texte. GitHub kann daraus ein strukturiertes Praxis-Wissenssystem machen.

Geeignet sind:

- Vorlagen für Beratungsgespräche und Folge-Termine
- Standardisierte Übungs-, Ernährungs- oder Reflexionspläne
- Prompt-Sammlungen für Content, Newsletter und Vorbereitung
- FAQ, AGB-Entwürfe, Onboarding-Unterlagen
- Eine private Ideen- und Aufgabenliste über Issues

Wichtig: **Kundendaten gehören nicht ungeprüft in GitHub.** Dort gehören anonymisierte Vorlagen, Methoden und Wissen — nicht Gesundheitsdaten, Messwerte oder persönliche Angaben.

## Reisebüros: eher Content und Website

Für Reisebüros ist GitHub vor allem dann sinnvoll, wenn du ihre Website, SEO-Texte, Reisebeschreibungen, Landingpages oder Newsletter betreust. Dort kannst du Inhalte, Änderungshistorie, SEO-Checklisten und Freigabeprozesse versionieren.

Mögliche Anwendung:

- Reise- und Destinationstexte als wiederverwendbare Bausteine
- Saisonale Angebotsseiten und Landingpages
- FAQ zu Einreise, Versicherung, Stornierung, Zahlung
- Content-Kalender und SEO-Aufgaben als Issues
- Automatische Prüfungen für Links, Formulare oder Sitemap-Änderungen

Für das Tagesgeschäft — Buchungen, Kund:innenkommunikation, Zahlungen — ist GitHub dagegen **kein Ersatz** für ein Reisebüro-CRM, Buchungssystem oder DSGVO-konforme Kundenablage.

## Handwerker: Nutzen entsteht durch dich

Handwerksbetriebe haben oft den grössten Digitalisierungsrückstand, aber auch die geringste Affinität zu Entwickler-Tools. GitHub ist für sie daher kein Selbstbedienungsinstrument, sondern eine **Hintergrund-Infrastruktur**, mit der du ihnen wiederholbare digitale Abläufe baust.

Praktisch denkbar:

- Website, Referenzen, Leistungen und lokale SEO-Texte versionieren
- Offerten-, Aufmass- und Übergabe-Checklisten pflegen
- Vorlagen für Offerten, Reklamationen und Projektdokumentation
- Automatische wöchentliche Berichte aus Excel-, Buchhaltungs- oder Zeiterfassungsdaten
- Ein einfaches KPI-Dashboard, das aus bestehenden Daten betriebliche Steuerung ermöglicht

Der Handwerker müsste GitHub dabei kaum öffnen: Er erhält Checklisten, Offerten oder Reports in vertrauter Form, während du die Struktur und Automatisierung im Repository pflegst.

## Wie du es vermarkten kannst

Statt „Ich richte Ihnen GitHub ein“ würde ich drei konkrete Angebote formulieren:

- **Für Autor:innen:** „Manuskript- und Recherche-Archiv mit sauberer Versionshistorie“
- **Für Berater:innen:** „Digitales Praxis-Handbuch mit Vorlagen, Prompt-Bibliothek und Aufgabensteuerung“
- **Für Reisebüros und Handwerker:** „Pflegeleichtes Website-, Content- und Prozess-System, das ich für Sie betreue“

GitHub ist damit kein Produkt für die Kundschaft, sondern dein **Liefer- und Wartungswerkzeug** — ausser bei Buchautoren und technisch affinen Beratenden, bei denen es auch direkt als Arbeitswerkzeug Sinn ergibt.

# Welcher Hostinganbieter ermöglicht es, Inhalte von GitHub zu holen und zu publizieren?

Mehrere Anbieter können Inhalte direkt aus einem GitHub-Repository holen, bauen und automatisch veröffentlichen. Für deine Kundenprojekte sind **Cloudflare Pages**, **Netlify** und **Vercel** die praktischsten Optionen; für rein statische Seiten ist auch **GitHub Pages** möglich.[^5_1][^5_2][^5_3]

## Geeignete Anbieter

| Anbieter | GitHub-Anbindung | Besonders geeignet für | Hinweis |
| :-- | :-- | :-- | :-- |
| **Cloudflare Pages** | Repository verbinden; bei jedem Push wird automatisch gebaut und deployt. [^5_1][^5_4] | Websites, Blogs, Dokumentationen, statische Kundenseiten; gute globale Performance | Starke Wahl, wenn du einfache, schnelle Sites ohne komplexes Backend willst. |
| **Netlify** | GitHub-Repo verbinden; jeder Push auf die Produktions-Branch löst Build und Deployment aus. [^5_2] | Marketing-Sites, Landingpages, Formulare, CMS-Workflows | Sehr einsteigerfreundlich, mit Vorschau-Deployments und Formularfunktionen. |
| **Vercel** | Repository importieren; Framework und Build werden meist automatisch erkannt. [^5_3] | Next.js, Astro, moderne Frontend-Projekte, dynamischere Sites | Besonders stark, wenn du später interaktive Anwendungen oder serverseitige Funktionen brauchst. |
| **GitHub Pages** | Direkt aus GitHub; meist per GitHub Actions gebaut und veröffentlicht. [^5_3][^5_5] | Kostenlose statische Websites, Portfolios, Dokumentation | Kostenlos, aber weniger komfortabel bei Formularen, Umgebungsvariablen und komplexeren Workflows. |
| **Render** | Automatische Deployments aus GitHub/GitLab; unterstützt statische Sites, Web-Services und Datenbanken. [^5_6] | Projekte mit Backend, API oder Datenbank | Interessant, wenn aus einer Kunden-Website später eine kleine Anwendung wird. |
| **Azure Static Web Apps** | GitHub Actions übernimmt Build und Deployment; Custom Domain und SSL inklusive. [^5_7] | Microsoft-/Azure-Umfeld, statische Sites plus Functions | Sinnvoll, wenn du oder der Kunde bereits Azure nutzt. |

## Wie der Ablauf funktioniert

1. Du pflegst Inhalte, Texte oder Website-Dateien in einem GitHub-Repository.
2. Du verbindest dieses Repository im Hosting-Dashboard des Anbieters.
3. Der Anbieter holt den Code, führt gegebenenfalls einen Build aus und veröffentlicht das Ergebnis.
4. Bei jedem Push auf die festgelegte Branch — meist `main` — wird die Website automatisch aktualisiert. Cloudflare beschreibt diesen Ablauf ausdrücklich als automatische Builds und Deployments bei jedem Push.[^5_4][^5_1]
5. Optional hängst du eine eigene Domain an, etwa `kunde.ch`, statt der Standard-URL wie `projekt.pages.dev`.[^5_8][^5_9]

## Empfehlung für deine Kunden

- **Reisebüros:** Cloudflare Pages oder Netlify für schnelle, redaktionell pflegbare Websites mit Reisedestinationen, Landingpages und FAQ.
- **Berater:innen:** Netlify oder Cloudflare Pages für Website, Blog, Lead-Magnet-Seiten und Newsletter-Landingpages.
- **Buchautoren:** Cloudflare Pages oder GitHub Pages für Autorenwebsite, Leseproben, Pressekit und Buchseiten.
- **Handwerker:** Cloudflare Pages oder Netlify, idealerweise von dir betreut; der Kunde pflegt Inhalte bequem über ein CMS oder einfache Markdown-Dateien, GitHub bleibt im Hintergrund.

**Meine pragmatische Standardwahl wäre Cloudflare Pages:** einfach mit GitHub verbunden, schnell, global verteilt und gut geeignet für die meisten statischen Kundenwebsites. Netlify wäre die Alternative, wenn du besonders einfache Formulare, Vorschauen und CMS-Integrationen priorisierst.[^5_2][^5_1]
