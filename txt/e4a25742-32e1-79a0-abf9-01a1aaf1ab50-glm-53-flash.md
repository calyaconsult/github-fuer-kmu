**Wozu kann ich als Nicht-Programmierer `git` nutzen?** Überall dort, wo Dokumente über längere Zeit entstehen und sich laufend ändern, lohnt sich der Einsatz. Wer kennt es nicht: Ordner voller Dateien mit Namen wie "Bericht_final_v2_NEU.docx", und am Ende weiss niemand mehr, welche Fassung die aktuelle ist und wer welchen Absatz verändert hat. Genau dafür ist `git` gemacht: Statt immer neue Kopien anzulegen, legt man nach jedem Arbeitsschritt einen Commit ab und kann später jederzeit nachvollziehen, was sich wann geändert hat – und einzelne Änderungen gezielt rückgängig machen. Typische Einsatzgebiete sind Dissertationen, Bücher, Berichte, Protokolle, Verträge, Übersetzungen oder technische Dokumentationen. Am meisten profitiert, wer in Textformaten wie Markdown oder LaTeX arbeitet, denn dort zeigt `git` jede Änderung zeilenweise an. Aber auch Website-Inhalte, Lehrmaterialien, Konfigurationsdateien oder tabellarische Daten im CSV-Format lassen sich so sauber versionieren – und selbst bei Word-Dateien geht keine frühere Fassung je verloren.

Besonders interessant wird `git`, wenn mehrere Personen an denselben Dokumenten arbeiten. Statt Dateien per E-Mail hin und her zu schicken, arbeitet jede Person auf ihrer eigenen Kopie des Repositorys, und die Beiträge lassen sich später geordnet zusammenführen. Zu jeder Änderung ist protokolliert, wer sie wann vorgenommen hat – die Frage "Wer hat das geändert?" gerät also nie wieder zum Rätsel. Nebenbei entsteht ein lückenloses Protokoll der gesamten Projektgeschichte.

**Brauche ich dazu einen Server?** Nein – `git` kommt, wie eingangs erwähnt, vollständig ohne Server aus; die gesamte Versionsgeschichte liegt im Ordner auf dem eigenen Rechner. Eine zentrale Kopie im Internet wird erst dann spannend, wenn man das Projekt auf mehreren Computern bearbeiten, mit anderen zusammenarbeiten, ein externes Backup anlegen oder Inhalte veröffentlichen will. Dafür ist GitHub die bekannteste Adresse; daneben gibt es etwa GitLab und Bitbucket, und mit Software wie Gitea lässt sich eine solche gemeinsame Ablage sogar auf dem eigenen Server betreiben. Ein GitHub-Konto ist übrigens kostenlos, und auch private Repositories, die nur für einen selbst oder ein ausgewähltes Team sichtbar sind, kosten nichts. Wer ganz ohne Internet arbeiten möchte, kann ein Repository sogar einfach auf einen USB-Stick oder eine externe Festplatte kopieren: Für `git` ist das ein Ablageort wie jeder andere. Dass sich mit GitHub Pages ausserdem kostenfrei einfache Websites veröffentlichen lassen, sei der Vollständigkeit halber erwähnt – auch das ist ein Thema für sich.

**Brauche ich Linux? Geht das auch unter Windows oder macOS?** `git` wurde zwar 2005 für die Entwicklung des Linux-Kernels geschrieben, läuft heute aber auf allen gängigen Systemen – und als freie Software überall kostenlos. Unter Windows installiert man am einfachsten das Paket "Git for Windows", das die Befehlszeilenwerkzeuge mitbringt; dazu gibt es mit TortoiseGit eine direkte Einbindung in den Datei-Explorer und mit GitHub Desktop eine besonders einsteigerfreundliche grafische Oberfläche, mit der sich Repositories anlegen, Änderungen ansehen und Commits erstellen lassen – ganz ohne Kommandozeile. Auf dem Mac ist `git` in der Regel bereits vorhanden; falls nicht, bietet das System beim ersten Aufruf an, es automatisch nachzuinstallieren. Auch hier existieren grafische Werkzeuge wie GitHub Desktop oder Tower, und viele Editoren wie Visual Studio Code binden `git` fest ein. Wichtig ist vor allem: Die Befehle und Konzepte sind auf allen Systemen identisch. Eine Einführung, die für Linux geschrieben ist, funktioniert also unverändert auch unter Windows oder macOS.

Für erste Experimente genügt somit ein ganz gewöhnlicher Rechner – am besten zusammen mit einem Ordner voller Textdateien.
