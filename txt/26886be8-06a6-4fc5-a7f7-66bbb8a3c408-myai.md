# GitHub für Ein-Mann-Unternehmen: Viel mehr als nur Code

Wer bei GitHub nur an Programmierer denkt, verschenkt viel Potenzial. Als Solo-Selbständiger nutze ich es als **versioniertes Arbeits- und Wissenssystem**. Es ist nachvollziehbar, durchsuchbar und im Basisumfang kostenlos.

## Wie ich GitHub selbst nutze

**1. Code-Repository:** Der Klassiker. Skripte, Automatisierungen und Website-Code liegen versioniert an einem Ort. Jede Änderung lässt sich nachvollziehen und rückgängig machen.

**2. Zeitnachweis für Texte:** Wenn ich einen Text via Web-Upload auf GitHub hochlade, erhält er einen verifizierten Zeitstempel. Ist das Repository öffentlich, kann jedermann diesen Zeitstempel einsehen. Wird der Text nach dem Upload nicht mehr verändert, kann der Zeitstempel als Nachweis dienen, dass der Text zum Zeitpunkt *t* bereits existierte. Für gerichtsverwertbare Nachweise sollte jedoch eine offizielle Zeitstempelungsstelle (TSA) hinzugezogen werden.

**3. Mini-CMS für statische Websites:** Texte liegen als Markdown-Dateien im Repository. Ein Push genügt, und die Website aktualisiert sich automatisch. Ein Datenbank-CMS mit Updates und Sicherheitslücken brauche ich dafür nicht.

**4. Goodies und Giveaways:** Checklisten, Vorlagen und Prompt-Sammlungen kann ich in öffentlichen Repositories oder als Release-Downloads anbieten. Das ist ein einfacher Weg, Kompetenz zu zeigen und Vertrauen aufzubauen.

## Weitere Einsatzmöglichkeiten

- **Kunden- und Projektarchiv:** Briefings, Konzepte und Checklisten, bei denen jede Fassung datiert bleibt.
- **Playbooks und Vorlagen:** Audits, Workshop-Abläufe und Angebotsbausteine, die du iterativ verbesserst.
- **Redaktionsprojekte:** Manuskripte, Recherche und Lektoratsstände in Markdown.
- **Leichte Projektsteuerung:** Issues und Boards für To-dos, Ideen und Kundenanfragen.
- **Automatisierung:** Mit GitHub Actions laufen geplante Skripte, etwa für Berichte oder Link-Checks.

Praktischer Start: ein privates Repository mit drei Ordnern für Checklisten, Vorlagen und eine Ideenliste. Nach ein paar Wochen siehst du, ob es dir etwas bringt.

**Grenzen:** Vertrauliche Kundendaten, Verträge und Gesundheitsdaten gehören nicht in GitHub, sondern in einen geeigneten Schweizer oder EU-Speicher. Für rein visuelles Arbeiten sind Notion oder Obsidian oft angenehmer.

## Was kostet das?

| Angebot | Preis | Fazit |
| :-- | --: | :-- |
| **GitHub Free** | 0 USD | Unbegrenzt private und öffentliche Repositories, Issues, Projects und 2.000 Actions-Minuten pro Monat. Für Solo-Betriebe meist ausreichend. |
| **GitHub Team** | ca. 4 USD pro Nutzer/Monat | Erst nötig bei geschützten Branches oder Zusammenarbeit im Team. |
| **Copilot Free** | 0 USD | Zum Ausprobieren. |
| **Copilot Pro** | 10 USD/Monat | Die passende Stufe für regelmässige Solo-Nutzung. |
| **Copilot Pro+** | 39 USD/Monat | Nur bei intensiver Nutzung von Premium-Modellen und Agenten. |
| **Copilot Business** | 19 USD pro Sitz/Monat | Eher für Organisationen mit zentraler Verwaltung. |

Seit Juni 2026 rechnet Copilot über «AI Credits» ab (1 Credit = 0,01 USD). Pro enthält 1.500 Credits. Zusätzliche Credits kosten extra. Code-Vervollständigungen in bezahlten Plänen sind davon ausgenommen. Zur USD-Gebühr kommen in der Schweiz je nach Zahlungsweg noch Umrechnungskosten.

## Welche Kunden profitieren?

| Kundentyp | Potenzial | Typische Anwendung |
| :-- | :-- | :-- |
| **Buchautoren** | Sehr hoch | Ein Repository pro Buch mit Kapiteln als Markdown, Recherche und Korrekturaufgaben als Issues. Schluss mit `Manuskript_final_v7_NEU.docx`. |
| **Berater:innen** (Ernährung, Fitness, Persönlichkeitsentwicklung) | Hoch | Ein «Practice OS» mit Gesprächsleitfäden, Plänen, Onboarding und Prompt-Bibliothek. Keine Kundendaten, nur anonymisierte Vorlagen. |
| **Reisebüros** | Mittel | Website-Inhalte, Destinationstexte, FAQ, Content-Kalender. Du betreust das Repo, für Buchungen und CRM ist es kein Ersatz. |
| **Handwerker** | Mittel bis niedrig | Website, Offerten- und Übergabe-Checklisten, automatische Berichte aus Excel-Daten. GitHub bleibt im Hintergrund. |

Bei den meisten Kunden ist GitHub dein **Liefer- und Wartungswerkzeug** und nicht deren Arbeitsplattform. Verkaufe deshalb nicht «GitHub-Einrichtung», sondern Ergebnisse. Das sind zum Beispiel ein Manuskript-Archiv mit Versionshistorie, ein digitales Praxis-Handbuch oder ein pflegeleichtes Website-System.

## Vom Repository zur Website: Hosting

Mehrere Anbieter holen Inhalte direkt aus GitHub und veröffentlichen sie bei jedem Push automatisch:

| Anbieter | Stärke |
| :-- | :-- |
| **Cloudflare Pages** | Schnell, global verteilt, ideal für statische Kundenseiten. Mein Standard. |
| **Netlify** | Sehr einsteigerfreundlich, mit Vorschau-Deployments und Formularfunktion. |
| **Vercel** | Stark bei modernen Frameworks wie Next.js oder Astro und dynamischeren Projekten. |
| **GitHub Pages** | Kostenlos und direkt integriert, für Portfolios und Dokumentation. |
| **Render** | Sinnvoll, wenn später ein Backend oder eine Datenbank dazukommt. |

**Ablauf:** Inhalte im Repository pflegen, Repository beim Anbieter verbinden, pushen, und die Seite ist live. Optional hängst du eine eigene Domain wie `kunde.ch` an.

## Fazit

GitHub ist ein gut getarntes Allzweckwerkzeug für Wissensarbeit: Versionierung, Aufgaben, Automatisierung und Publishing in einem Konto, das nichts kostet. Starte klein mit einem privaten Repository und einem konkreten Anwendungsfall.
